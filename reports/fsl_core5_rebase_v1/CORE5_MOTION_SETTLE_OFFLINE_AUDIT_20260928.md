# Core5 motion-settle offline audit — 2026-09-28

Status: read-only diagnostic; no Android boundary, threshold, model, gate, or production change. Samsung saved timestamped landmark/225-feature frames were replayed deterministically through the **existing, unused debug** `AUTO_MOTION` rule in `Core5Recorder` (full-vector adjacent-frame L2 < 0.08 continuously for 900 ms, with at least 1,200 ms since first hand). This is not a proposed production threshold.

The current debug rule would trigger before the recorded ending in **0/18 AUTO_LEGACY events**. It also would not trigger in any of the 16 saved MANUAL non-sign events. In an offline sensitivity scan that retained the same 900/1,200 ms dwell/floor but varied the adjacent-frame L2 cutoff, 0.2, 0.4, 0.8, and 1.2 still triggered **0/18** automatic events. At 2.0, seven automatic events would trigger (HELLO 1/4, NO 3/3, UNDERSTAND 3/3), but THANK YOU 0/4 and YES 0/4 still would not. This scan is exploratory, **not** authorization to set 2.0 or any new threshold.

The explicit mid-frame visible/still THANK YOU hold (`55aa3c3a`) has a median last-ten adjacent-frame full-feature L2 of 2.758 and p90 of 11.902. The other raw-correct THANK YOU timeout (`4bd6fd5b`) has 3.215 / 8.945. These large values are compatible with detector jitter, finger articulation, hand/pose landmark variation, or actual residual movement; landmarks alone cannot distinguish those causes. They show why an unnormalized full-225-vector 0.08 cutoff does not operationally represent "still hands" on this Samsung. The existing rule also uses timestamp dwell but **not** timestamp-normalized velocity. A class-agnostic candidate should be based on robust anatomical wrist/hand-centroid displacement per elapsed time, with separate tracking-quality handling, not a blind threshold increase on the same feature norm.

Private per-event delta distributions, exact trigger indices/timestamps, and sensitivity counts are preserved in `D:/VoxGest/evidence/fsl_core5_rebase_v1/core5_existing_debug_motion_boundary_replay_20260928.json` and `core5_motion_threshold_sensitivity_20260928.json`. The offline test does not have an independent human sign-end timestamp or video; it also does not rerun the classifier/gate on hypothetical truncated events. MANUAL negatives are not equivalent to automatic arming. Therefore it establishes that the **present** debug `AUTO_MOTION` boundary is ineffective on this sample, not that any alternative boundary is safe.

Decision: do not install or promote `AUTO_MOTION` as a fix. A next experimental iteration must first reconstruct candidate cut points and final `[48,225]` tensors from held-out saved events, replay those tensors through TFLite and the frozen gate, and explicitly check premature truncation and moving non-sign false accepts. Any resulting Android implementation must remain an isolated debug mode. The separately observed 5/16 frozen-gate negative false accepts and YES raw confusion continue to block the user-facing Core5 path even if timeout behavior is repaired.
