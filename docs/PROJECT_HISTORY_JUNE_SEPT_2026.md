# VoxGest Project History — June to September 2026

Purpose: keep a concise, evidence-oriented history inside GitHub so new engineers/agents can understand why the current architecture exists without relying on chat memory.

Rule: each milestone gets a 1–2 line summary. Historical work is not automatically current production truth; current handoff files and physical-device evidence take precedence.

---

## June 2026

### June 30 — FSL-105 handedness audit tooling
`93_classify_fsl105_handedness.py` was created/used to classify FSL-105 handedness behavior and support safer left/right handling. This work helped expose the need to treat anatomical handedness as data rather than infer it from mirrored display coordinates.

Evidence references: `scripts_ml/93_classify_fsl105_handedness.py`, later July handedness reports.

### June — transition toward broader FSL data governance
The project moved away from treating a small one-hand demo as sufficient and began formalizing FSL-105 source auditing, handedness checks, and a future full-sign representation. Exact day-level June records are incomplete in the currently recovered archive, so this is retained as a bounded historical summary rather than a fabricated detailed chronology.

## July 2026

### July 1–6 — handedness reports completed
FSL-105 handedness review artifacts were generated by class and video, including manual-review and failed-video reports. These artifacts became part of the evidence used to avoid unsafe silent left/right swapping.

Evidence references: `fsl105_handedness_manual_review.csv`, `fsl105_handedness_by_class.csv`, `fsl105_handedness_by_video.csv`, `fsl105_handedness_failed_videos.csv`.

### July — manuscript / defense architecture consolidation
The Chapter 1–3 defense manuscript described VoxGest as a bidirectional Android accessibility prototype with sign recognition, speech communication, and Avatar feedback. This was still an intermediate architecture and later technical changes must not be back-propagated into July as if they already existed.

Evidence reference: `VoxGest_Chapter1_3_Oral_Defense_final.pdf`.

## August 2026

### August 25–26 — FSL-105 temporal training and Android handoff matured
The repository gained FSL-105 extraction/training tools, TCN and RD-TCN evaluation, rejection calibration, split/audit reports, and Android handoff artifacts. This phase made leakage-aware model comparison and reproducible Android export a formal part of the workflow.

Evidence references include: `76_extract_fsl105_features.py`, `78_train_fsl_rdtcn.py`, `79_train_fsl_tcn.py`, `fsl_tcn_evaluation.json`, `fsl_rdtcn_evaluation.json`, `fsl105_dataset_audit.*`, `android_handoff_next_steps.md`.

### August 26 — FullSign225 experimental lane consolidated
FullSign225 work combined pose 99 + anatomical left hand 63 + anatomical right hand 63, and team/manual audits were consolidated. This established the geometry contract later used by both recognition and the 3D Avatar retargeting pipeline.

Evidence references: `fullsign225_*` audits and extraction summaries.

### August 28–30 — raw-video and Avatar reference extraction expanded
Tools were added to import external FSL videos, export FSL-105 Avatar trajectories, select Avatar reference videos, run raw-video self-tests, and extract FullSign225 from raw video. This connected the classifier data-governance work to a reusable animation-reference pipeline while keeping Avatar trajectories separate from classifier windows.

Evidence references: `export_fsl105_avatar_landmarks*.py`, `select_fsl105_avatar_reference_videos.py`, `run_fsl105_raw_video_selftest.py`, `extract_fsl105_fullsign225.py`, `fullsign225_feature_builder.py`.

## September 2026

### September 4 — purchased 3D Avatar source and first retargeting audit
The purchased Blender Avatar was inspected and confirmed to contain detailed independent finger chains. The first HELLO retargeting workflow identified two concrete script issues: Blender Text Editor execution failed on a hard `--` argument assumption, and the original arm mapping incorrectly used elbow→wrist for both upper arm and forearm.

Evidence reference: `VOXGEST_AVATAR_COMPLETED_WORK_SUMMARY.txt`.

### September 6 — Android presentation and bilingual UI hardening
The Android presentation layer added English/Filipino interface support, independent English/Filipino/Both message presentation, persisted settings, display-only mirror control, Conversation, Listen/STT, Guide, and safety-bounded user-facing output. The recognition contracts were deliberately protected during this UI sprint.

Evidence references: `CAPSTONE_UI_V2_PROGRESS_20260906.md`, `CAPSTONE_UI_V2_FINAL_20260906.md`.

### Early September — generalized Avatar solver and CORE3 proof
The Avatar lane advanced to a frozen generalized Blender retargeter, `retarget_general_B32_release_candidate_v1`, with HELLO, MILK and RICE serving as CORE3 proof motions. User-facing vocabulary expansion was then reframed as a quality-first, fast-fail process rather than an arbitrary sign-count target.

Historical status: CORE3 must still be revalidated in the recovered safe workspace before current PASS claims are made.

### September 9 — CORE3 Android Filament integration
A 28,123,308-byte CORE3 GLB with `FSL_HELLO`, `FSL_MILK`, and `FSL_RICE` was integrated into the Android Avatar path. Filament loading, lazy creation, checksum validation and JVM/build gates progressed, while physical testing exposed/confirmed rendering lifecycle concerns including SurfaceView/Compose z-order and native teardown risk.

Evidence references: September 9 CORE3 Android integration logs and `CORE3_AVATAR_ANDROID_INTEGRATION_20260909.md` where present.

### September 9 — storage failure forced recovery discipline
During physical-device evidence capture the old D: volume disappeared. From this point the project established a strict rule: do not access/write the historical D: workspace; recovered work must use safe C: storage and GitHub as shared source of truth.

### September 10–12 — repository recovery and recognition evidence reconstruction
The project was recovered to `C:\VOXGEST_RECOVERY_20260910\New_VovGest_GIT`, with GitHub handoff discipline, test/build verification, protected assets and architecture decisions reconstructed. The recognition lane recovered strong FSL-105 offline results while explicitly separating them from live-device generalization.

### September 12–13 — Mapúa Transactional FSL rescue experiment
A 1,107-video/26-class Transactional FSL dataset was audited, then a 14-class exact-overlap rescue experiment trained PASS-only source clips. RD-TCN48 won development comparison and achieved exploratory sealed clip-level accuracy of about 98.21% and macro-F1 about 97.96%; signer IDs were unavailable, so signer-independent performance is not claimed.

### September 13 — Samsung Series 1 exposed live temporal mismatch
HELLO was eventually recognized and presented as `Kumusta`, but response required retries and more than a minute. Investigation identified a key train/live mismatch: training used complete-trajectory temporal resampling while Android used a rolling 48-frame window; a dedicated live-segmentation fix was started.

### September 13 — Codex usage cutoff during live-segmentation implementation
Series-1 evidence was preserved locally and a rollback-safe live-segment branch was started, but Codex usage limits interrupted completion before build/device A/B testing and GitHub publication. This is an interrupted implementation, not a failed model experiment.

### September 14 — dedicated Astra Avatar engineering lane created
A separate `avatar/astra-calibration-20260914` branch was established so the app developer's own Codex/Astra can continue Blender calibration, user-facing vocabulary expansion, runtime export and Android Avatar validation independently from Sol's recognition work.
