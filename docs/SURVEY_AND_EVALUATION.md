# Survey and Evaluation

## Quality Framework

VoxGest uses selected ISO/IEC 25010 quality characteristics:

- Functional Suitability
- Performance Efficiency
- Reliability
- Usability

## Evaluator Roles

### IT Experts

Primary focus:

- function completeness
- implementation feasibility
- app stability
- response time
- on-device behavior
- failure/recovery handling

### FSL Experts

Primary focus:

- linguistic recognizability
- handshape/orientation/location/movement
- signing-space use
- Avatar intelligibility
- candidate-action corrections
- whether a representation should be accepted as FSL

### Target / Representative Participants

Primary focus:

- ease of use
- readability
- navigation
- perceived responsiveness
- communication usefulness
- clarity of errors and fallback options

Specialist FSL judgments should not be treated as interchangeable with general usability judgments.

## Recommended Session Flow

1. Explain prototype scope and obtain informed consent.
2. Demonstrate onboarding and basic navigation.
3. Test the controlled SIGN vocabulary.
4. Demonstrate text/speech output.
5. Demonstrate LISTEN:
   - microphone if device STT works;
   - manual Play Signs regardless of STT availability.
6. Demonstrate Conversation / Board / Guide as relevant.
7. Complete the questionnaire.
8. Collect one or more open-ended improvement comments.

## Survey Instrument

A concise 5-point Likert instrument may group questions by the four selected quality characteristics. Weighted means may summarize each category, while open-ended comments capture qualitative improvements.

## Reporting

Document:

- exact APK/build used
- device
- supported recognition set
- supported/candidate Avatar set
- known limitations
- failures observed during testing
- respondent group
- evaluation date

Do not silently change the evaluated APK between respondent groups without documenting the new build as a separate condition.
